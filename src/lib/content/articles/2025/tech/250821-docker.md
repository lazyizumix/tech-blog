# はじめに

最近の開発現場では「Docker」という単語をよく耳にしないかな？？

さっくり言うと、

- **Docker** = コンテナを作って動かすツール

ここからもうちょっと掘り下げていくよ。
ただし、抽象的な概念のみで具体的にどのように使うのかについては別の記事でやっていく予定だよ。

## Docker（ドッカー） とは？

Docker は OSS の仮想化技術で、一つのサーバー上に複数のアプリケーション実行環境（コンテナ）を立ち上げられるよ。

### 従来との違い

昔は VM（バーチャルマシン）を使って、1つのサーバー上に複数の仮想環境（サーバーとOS）を構築していたけど、OSごと動かすから重たいし起動も遅いという欠点があったんだ。

一方 Docker は、「アプリを動かすのに必要な部分だけ」を分離して、ホストのOSを共用する仕組みになっているよ。
そのおかげで、非常に軽量かつ高速に動作するようになったんだ。

どちらも「イメージ」という形で環境を持ち運べるんだけど、

- VMイメージ -> OSごと入っているので数十GB単位で巨大で現実的ではない
  - 構成イメージ：[ハードウェア] -> [ホストOS] -> [ゲストOS] -> [アプリ]
- Dockerイメージ -> アプリ+必要なライブラリだけなので数百MB程度
  - 構成イメージ：[ハードウェア] -> [ホストOS] -> [Docker] -> [アプリ]

この差がめちゃくちゃ大きい。

例えるなら、夏に冷たい飲み物が欲しい時に、

- VM -> 冷蔵庫ごと持ち運ぶ
- Docker -> 水筒やクーラーボックスを持ち歩く

そんな違いだね。

VMの「重い・遅い・扱いづらい」の三重苦を解決したのが **Docker** ということだね。
まさに革命的な技術だよ！！

## コンテナとは？

コンテナは「お弁当」だと思ってみてね。
お弁当の中には、料理された色々な食材が詰め込まれているでしょ？

コンテナも同じで、箱の中にアプリを動かすために必要な情報が詰め込まれているよ。
具体的には、アプリのソースコードや設定ファイル、ライブラリ、ミドルウェア、実行環境などなど....

お弁当は家で作った状態のまま別のところに持ち運んで食べる事ができるよね。
コンテナも「**どこで実行しても同じ環境が再現できる**」というメリットがあるよ。

## コンテナってどう作るの？

押さえるポイントとしては3つだけ。

### 1. Dockerfile（レシピ）

Dockerfileとは、どんなコンテナ（お弁当）を作るかを書いたレシピだよ。
お弁当を作る際は、どんな料理を入れるか考えるよね。おにぎりを入れたり、タコさんウインナーを入れたり....
コンテナも同じで、「どのOSを使うか」「どんなライブラリを入れるか」などを事前に設定ファイルとして定義するよ
その設定ファイルが**Dockerfile**だよ。

### 2. コンテナイメージ（完成品）

コンテナイメージは、Dockerfileを元に作った情報の塊（料理）だよ。
Dockerfileをビルド（変換）するとコンテナイメージが作られるんだ。
DockerfileはあくまでどのようなOS、ライブラリを使うかなどが定義されているファイルなので、そのファイルを元に実際に動かせる状態に変換したものがコンテナイメージだよ。

お弁当の中に入れるおにぎりやタコさんウインナーも、料理（ビルド）という工程を経て作られるよね。
いわば料理後の完成品だね。

### 3. コンテナ（お弁当）

コンテナは、コンテナイメージを実際に動かした状態だよ。
お弁当箱に料理を詰めて「さぁ食べられるぞ！」ってなった状態が **コンテナ** だね。

## まとめ

まとめると、
Docker は、コンテナを「作る、動かす」を簡単にするためのツール。
VM より軽くて早く、環境をどこでも再現できるのが大きな特徴だよ。
